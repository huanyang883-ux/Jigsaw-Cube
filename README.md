# 魔方拼图

PixiJS + Three.js 本地 H5 拼图，设计分辨率 **1080 × 1920**，等比例适配手机竖屏。界面使用图标与道具数量，包含甜品、动物与六大洲三个可玩魔方，五阶保留沙漏入口。

## 启动与手机试玩

Windows 安装 Node.js 22+ 后，双击 `start-game.cmd` 启动普通版，或双击 `start-game-test.cmd` 启动带重置账号和一键通关按钮的测试版，浏览器自动打开。两个脚本每次分别执行 `npm run build`、`npm run build:test`，确保启动的是最新源码与所选版本。`dist/` 和 `node_modules/` 不提交到 Git；新 clone 的项目首次启动会联网安装依赖，依赖安装完成后可离线启动。

正式发布使用 `npm run build`。如需预览当前构建，执行 `node scripts/serve.mjs --open`。两个启动脚本共用 `dist/` 和本地服务地址；切换版本后使用新打开的页面，其他已打开的页面需刷新。

开发服务和测试构建的首页左上角齿轮包含音效、重置与完成所有关卡三个按钮。正式构建仅保留音效，两个测试按钮及其点击逻辑由构建开关移除，不通过网址或存档开启。

服务监听 0.0.0.0，默认端口 4173，占用时寻找 4174–4182。启动窗口输出 LAN 地址，手机与电脑连接同一局域网后打开该地址。电脑需保持开机与服务运行，各设备独立保存进度。本机防火墙规则 SweetCubePuzzle-LAN 仅允许本地子网访问这些端口。

开发运行 npm install 和 npm run dev，默认地址 http://localhost:5173，同样支持局域网。

前 12 关独立试玩：在游戏地址后添加 `?trial=first12`，例如 `http://192.168.25.4:4173/?trial=first12`。试玩使用独立存档 `sweet-cube:trial:first12:v1`，从第 1 关开始，初始道具各 28 个；普通入口仍使用原来的 `sweet-cube:progress:v2`。试玩进度会保留，不会覆盖原存档。

全 78 关独立试玩：使用 `http://192.168.25.4:4173/?trial=all78`，从第 1 关开始体验整套新节奏，存档为 `sweet-cube:trial:all78:v1`。普通存档、前 12 关试玩存档和全关试玩存档互不覆盖。之前的试玩入口也可以继续向后玩新版关卡；更换入口不会删除其他入口的进度。外网测试时，在原外网地址后添加相同查询参数即可。

## Android 测试 APK

应用名 **JigsawCube**，包名 **com.huanyang.jigsawcube**。使用 Capacitor 8.6.2，`compileSdk = 36`、`targetSdk = 36`、`minSdk = 24`。测试 APK 使用 `npm run build:test`，首页齿轮可重置账号或完成全部关卡。174 关的图片、章节封面和引导手套随包安装，可离线游玩。手机的系统 WebView 需要支持游戏所用的 WebGL 2。

在 Windows 双击根目录的 **build-apk.cmd**，输入版本号（例如 `2.0.1`）并回车。脚本会构建网页、同步原生工程、编译调试 APK，并检查签名、包名、版本号和 SDK 版本。成功后输出到：

    builds/android/JigsawCube-2.0.1-debug.apk

同目录的 `.apk.sha256` 是校验值，`.apk.json` 记录包信息。构建失败时窗口会保留错误信息，进程返回非零退出码。重复构建同一版本会替换该版本的输出文件；不同版本的 APK 会分别保留。

命令行也可运行（省略版本号会提示输入，留空使用 package.json 中的版本）：

    node scripts/build-android.mjs 2.0.1

版本采用 `主版本.次版本.修订号`，自动转换为 Android 内部版本码 `主版本 × 1000000 + 次版本 × 1000 + 修订号`。次版本和修订号分别为 0–999，内部版本码不超过 Android 的 2100000000 上限。打包参数只影响 APK 的版本，不修改网页工程 package.json。安装更新时使用相同包名、相同签名和不低于已安装包的版本码，可保留应用存档；APK 存档与浏览器试玩存档彼此独立。

### 构建环境

- Node.js 22+、JDK 21、Android SDK Platform 36、Build-Tools 36.0.0；Gradle / Capacitor 子工程还会使用 Build-Tools 35.0.0。
- 当前制作机复用 `D:\Unity\2022.3.62f3\Editor\Data\PlaybackEngines\AndroidPlayer\SDK`；在其中补装 Build-Tools 35/36，原有 Unity 工具保留。
- Unity 自带的 JDK 11 不适用。本工程使用 `.local/android-toolchain/` 中单独下载并校验过 SHA-256 的 Eclipse Temurin JDK 21。脚本只为构建子进程设置环境，不修改系统 JAVA_HOME 或 Unity 配置。
- Gradle Wrapper 会自动下载所需版本；首次构建需要联网下载 npm / Gradle / Maven 依赖。生成的 APK 可以离线运行。
- 当前机器可直接使用 CMD，不依赖打开 Android Studio。若需使用 IDE 编辑原生工程，应使用支持 Capacitor 8 的新版 Android Studio。

机器路径保存在忽略提交的 `.local/android-build.json`，换机器后安装工具链并配置，例如：

```json
{
  "sdkPath": "D:/Unity/2022.3.62f3/Editor/Data/PlaybackEngines/AndroidPlayer/SDK",
  "javaHome": "D:/AI/Puzzle/.local/android-toolchain/jdk-21.0.13+9"
}
```

没有配置文件时，脚本会检查 ANDROID_HOME、ANDROID_SDK_ROOT、JAVA_HOME、Android 默认 SDK 位置和项目内 JDK。JDK 21 可以从 [Eclipse Adoptium](https://adoptium.net/temurin/releases/?version=21&os=windows&arch=x64) 获取。SDK、JDK、Gradle 缓存及 APK 不提交到 Git。

调试 APK 由 Android 工具自动签名，适合本地安装测试，不作为商店发布包。保留本机用户目录 `.android/debug.keystore`，后续测试更新可沿用同一签名；密钥文件不会提交到仓库。

### 图标与手机行为

- 图标采用二阶主题的 `#fbf1e3` 奶油色背景、三阶立体魔方和跨九格拼成的巧克力曲奇。源文件在 `resources/android/`；`npm run android:icons` 可重新生成各密度桌面图标和自适应图标。生成说明与提示词记录在 `resources/android/icon.prompt.txt`。
- 手机使用竖屏和沉浸显示，并为刘海/系统手势区域预留安全空间。系统返回先关闭弹窗，再从拼图返回章节、从章节返回首页；首页返回会将应用放入后台。
- 进入后台时保存进度、暂停音效并停止累计游玩时间，回到前台后恢复。桌面浏览器仍可按原方式运行。
- `npm test` 验证玩法和版本码；`npm run test:android` 在开发服务器上模拟原生桥，检查安全区域、返回导航、音效和存档。该浏览器检查不代替 Android 真机测试。

## 游戏内容

- 首页魔方缓慢随机旋转，拖动可自由旋转查看，松手后恢复慢转。左右立体箭头切换二、三、四、五阶，拖动不会切换主题。
- 启动时按当前存档展示进度对应的魔方，并让当前章节朝向正面；已解锁三阶就直接展示三阶，三阶通关后展示四阶，全部通关后仍展示四阶最后一面，不进入五阶占位。普通与试玩入口分别读取自己的存档，首次加载与后台预取也跟随当前主题。
- 测试版首页齿轮内的环形箭头可重置当前账号，确认框仅保留必要的英文说明，叉号取消、勾号确认。重置后返回二阶首页，清空通关、未完成拼图和游玩记录，道具各恢复 28 次，音效与引导恢复初始设置；仅重置当前入口的存档，普通入口和两种试玩入口互不影响。
- 测试版齿轮内的奖杯立即完成全部 174 关，解锁二阶、三阶和四阶的全部章节，五阶占位仍不可进入。保留实际游玩记录、道具数量、音效与引导设置；清空未完成拼图，让下一次选关使用当前布局，不伪造通关步数或时长。只影响当前入口存档，重复点击结果相同。
- 背景独立于游戏区域按屏幕比例铺满，并额外放大 8%，适配长屏、平板、横屏和超宽屏。切换魔方时，背景与左右立体箭头以 0.8 秒柔和渐变切换奶油杏色、鼠尾草绿、蓝绿色和雾紫色；系统减少动态效果时立即切换。弹窗遮罩也覆盖整屏。
- 点击已解锁魔方或进入按钮，若还有未完成关卡则进入当前进度面，若已全部通关则进入点击时最正对屏幕的那一面；选关页底部的返回按钮恢复进入前的角度与大小，采用首页大按钮的风格并缩小约 11%。选关页左上角齿轮收纳音效，魔方面下方保留小圆点样式，每点对应当前面的一关，完成后变绿；二、三、四阶分别显示 4、9、16 点，随翻面更新，不显示进度条或数字。六个面的切换按钮位于底部返回按钮下方。
- 魔方面选关页不再显示顶部章节预览图；首页保留主题图标。局内眼睛预览和通关展示直接复用关卡图片，无独立缩略图资源。
- 六面顺序：正、右、背、左、上、下。一面完成后解锁下一面；二阶六面全部完成后解锁三阶，三阶完成后解锁四阶。
- 二阶：6 面 × 4 关，共 24 关。前 8 关为 3×3，第 9–24 关为 4×4，第 20 关回到 3×3 作为舒缓。六章是蛋糕、糖果、果冻、冰淇淋、巧克力、奶油。魔方阶数决定每面关卡数量，拼图区块数由每关独立配置。
- 三阶：6 面 × 9 关，共 54 关，每面八关 4×4，第 5 关为 5×5 难关，不再配置 3×3。六章依次为海洋生物、两栖生物、陆地生物、昆虫、鸟类、古生物。动物与栖息环境共同构图；古生物为照片质感的场景复原。
- 前 78 关总计 9 关 3×3、63 关 4×4、6 关 5×5。5×5 为第 29、38、47、56、65、74 关，25 块开局全部独立；四阶另外新增 96 个关卡位置。
- 游戏共使用 192 张内容图片，包括 18 张方形章节封面和 174 张独立的 2:3 关卡竖图。
- 棋盘保持原图比例，不拉伸、不裁切，图片平均切分。正确连接的拼片内部没有间隙，整组拖动时保持连续；未连接的边保留细缝。遇到边界无法移动时，整组沿拖拽方向轻微倾斜并回弹，实际位置不变。
- 拼片外缘采用小圆角、窄暖白边、细暗边与轻薄倒角，配柔和接触阴影。合组后内部白边、圆角和阴影同时消失，只保留整组外轮廓；内凹拐角由相邻三块共用一条连续小圆弧，白边不会断头，转角阴影不会重复叠黑；取消原来的绿色合组描边。翻牌背面和拼接闪白沿用圆角裁切，拖动时阴影略微加深。使用几何与材质着色实现，不增加图片资源或全屏模糊处理。
- 关卡出场：背面静止 0.5 秒 → 独立、小范围、由弱到强震动 1 秒 → 随机顺序、随机间隔翻面 2 秒，翻转时轻微抬起并平稳落定。第一帧即显示背面，动画期间锁定拼图与道具操作；系统开启减少动态效果时跳过震动与长演出。
- 首页顶部与魔方上方的主题图标、魔方牌背使用同一套主题：二阶是奶油杏色糖果，三阶是鼠尾草绿爪印，四阶是蓝绿色地球，五阶是原雾紫色小魔方。魔方外壳、牌背底色与描边配合各自背景；局内拼片背面沿用所属主题，竖图仅延展底板，图案保持原比例。图案由 Canvas 生成，不增加图片下载。
- 保留拖动交换、相邻合组、整组拖动、占位让位、提示、原图预览和进度存储。首页、选关页、拼图页的齿轮均位于左上角同一位置；拼图页齿轮展开返回与音效菜单，灯泡提示与眼睛预览移至右上角并保留数量角标，中间显示关卡进度条。点击空白处、再次点齿轮或按 Escape 收起；菜单打开时暂停拼图输入与有效游玩计时，也不响应魔方或面切换快捷键，收起时不会误拖下方卡牌。卡牌内容区最大 1008×1548，边框缩窄，在工具栏下方按原图比例居中适配。
- 拼片新连接成功时，刚连接成的整组显示一次约 0.6 秒的柔和珍珠白光泽：整体轻微提亮，一道宽而柔的斜向亮光连续掠过连接组，平滑消退；同时整组围绕共同中心放大约 3%，再平滑恢复，拼片内部保持无缝。主动拖动、被动让位和提示移动产生的新连接均会触发；一次移动形成多组新连接时，各组同时围绕自己的中心播放效果，未产生新连接的旧组不重复播放。继续拖动会立即结束反馈，不阻挡操作；普通拼接不喷射粒子。完成最后一步时恢复原来的彩色烟花粒子，完整拼图在原位展示 2 秒，再用 1 秒淡入、轻微上移与放大动画显示结算。减少动态效果时保留柔和提亮与结算淡入，省略缩放、扫光和烟花。结算动画完成后才能点击返回，等待期间主动返回会取消待弹出的结算，完成进度仍然保存。
- 提示和预览初始各 28 次，全关卡共用。每打开一次原图扣 1 次预览；提示实际移动成功才扣 1 次提示，计算失败或无可用提示不扣。用完按钮禁用，刷新、换关不会补充。沿用 v2 存档，旧存档保留全部进度并初始化道具数量。
- 未通过的魔方图块显示通用背面，通过后揭开章节图的对应切片。五阶仍为扩展占位，不能进入；隐藏面进度与重复状态图标，仅按钮显示沙漏。
- 白手套右手以食指点击、拖动做弱引导，没有文字、遮罩或强制操作。首页闲置 3 秒指向进入按钮，继续到 5 秒切换为旋转魔方示意；选关页每次闲置 5 秒指向当前面第一个未完成关卡，当前面已完成则先指向最新解锁页签，切换后再闲置 5 秒引导点击关卡，当前魔方全部通关后停止提示；第一次尚未掌握拖动时，在出场结束后示意一次合法拖动路径。
- 四种操作分别记入存档，首页和拼图操作掌握后永久关闭对应引导，选关引导不受已操作标记影响，旧存档同样生效。点击魔方与进入按钮均视为已掌握进入章节；提示道具自动移动不算玩家拖动；仅点击拼片不算拖动。任何输入都会隐藏当前手势并重计闲置时间，弹窗、加载、出场演出与后台页面不显示手势。

## 前 12 关难度样板

每面的小主题及原图保持一致，图片不跨章节混用。按实际构图人工标记了辨识难度，布局通过固定种子生成和离线求解筛选；玩家进入关卡时不会重新随机或运行难度搜索。

| 面 | 关卡 | 拼图区 | 难度节奏 | 已验证的完整解法步数 |
| --- | --- | --- | --- | --- |
| 蛋糕 | 1–4 | 3×3 | 引导、引导、普通、挑战 | 2、3、4、5 |
| 糖果 | 5–8 | 3×3 | 普通、普通、挑战、舒缓 | 4、5、5、4 |
| 果冻 | 9–12 | 4×4 | 新块数引导、普通、挑战、舒缓 | 6、7、8、6 |

前 8 关已排除所有更短解法，表中是最短步数。后 4 关已穷举排除四步以内通关，最短步数下界为 5；表中是找到并验证的可行解长度，不宣称最短。一步指一次合法拖动，可跨多格、可移动整组。玩家真实操作步数通常更高，实际难度仍需试玩校准。每关布局、种子、图像辨识备注、完整解法和验证数据在 `src/first12-layouts.json`。

提示按真实规则将某个未归位组移至其正确位置，不会挤走已正确归位的块；每次使用都会增加正确块数量，因此连续提示不会循环。提示仍需消耗道具，且不保证最少步数。

旧存档中正在玩的关卡保留原位置与原块数，包括旧版 3×3 果冻关；完成后重玩使用新版 4×4。通关、道具、音效及引导记录均继续保留。未完成关卡保存 `layoutVersion`、`gridSize` 和操作统计，加载时根据版本校验。

为了比较试玩体验，每关只在本机记录有效拖动数、提示与预览使用数、前台实际游玩时长，通关后写入存档 `records`；不联网发送，也不在游戏内增加文字或面板。计时排除加载、出场、后台和预览弹窗。后续平衡可以结合这些数据与玩家反馈。

前 12 关已按试玩反馈冻结。仅需专门重建原样板时运行 `npm run levels:generate:first12`。

96 个新布局全部零初始连接，经过旋转与镜像去重；每关保存完整可执行解法，路线长度不代表最短解。布局版本为 6，原 78 关图片、布局和解法保留。旧存档自动增加四阶进度，兼容第 10–16 关的续玩及记录。6×6/7×7 在复杂让位时使用有界搜索与多项式分配算法，保留拖动组完整，避免指数级计算阻塞手机操作。

`npm run levels:generate:continents` 可按固定种子重建四阶，计划在 `scripts/continent-plan.mjs`，布局在 `src/continent-layouts.json`。`npm run test:continents` 以手机触摸事件完成六洲全部 96 关，并检查逐章解锁、预览、提示、两位数关卡续玩、小屏与五阶入口。用 `?trial=continents` 可进入独立试玩存档。在测试版首页打开齿轮菜单，点击奖杯即可解锁全部章节。

## 图片和性能

- **当前及后续图片规范：关卡原图默认 1024×1536（严格 2:3），游戏 WebP 960×1440、质量 83；魔方章节贴图保持 1:1，运行时最长边上限 832px、质量 88，保留高分辨率原图。** 完整规范在 `art-source/AGENTS.md`。导出脚本在修改任何运行素材前检查全部原图，拒绝关卡比例错误、分辨率不足或非方形章节贴图；不自动裁切、拉伸或补边纠正。
- 全部关卡统一比例时，保留已验收的四张蛋糕 2:3 图与 12 张方形魔方贴图，对其余 74 张 3:4 图参考原画适度扩展上下场景。全部关卡配置逐字节保留，块数、初始排列、布局版本与已验证解法长度均不变，三阶全部 54 关继续零初始连接。原图备份、编辑提示词、生成对应关系和验证记录在 `art-source/experiments/all-levels-2x3-v1/`。此前实验章节中记录的旧尺寸与当次替换范围为历史记录。
- 魔方面图和牌背直接保留 sRGB 原色，不叠加外壳的强光照和色调映射，外壳仍使用立体光照。已移除全部 90 张未使用的缩略图及其生成、加载逻辑，减少约 1.4 MB 资源。
- HTML 内置无文字加载画面，主脚本下载期间也能显示。启动时准备手套、当前魔方朝向玩家的三张高清封面，以及由 18 张 160×160 封面合成的一张常驻预览图。跨阶滑入的第一帧就按存档显示已揭开的图块，高清封面就绪后原位替换，下载失败时继续显示相同画面的预览。选中关卡时才下载并解码该关图片，加载中显示图形进度条，失败显示重试图标。
- 下载后验证图片能否解码，避免损坏文件被误判为加载完成。脚本下载失败、资源报错或 45 秒没有进展时显示重试图标。首次点击普通重载；再次失败后点击会取消预取、清空资源内存缓存，仅删除 `sweet-cube:assets:` 名称前缀的 Cache Storage，并从网络刷新已使用的游戏资源，再重新进入游戏。浏览器没有选择性删除 HTTP 缓存的接口，因此 HTTP 缓存使用 `cache: 'reload'` 下载覆盖。清理或下载失败仍保留重试入口，不自动无限重试。
- 恢复控制代码内置在 HTML 中，主模块未下载也能使用；普通局域网 HTTP 无 Cache Storage 时也能强制下载。恢复计数只使用独立的 sessionStorage 键，完全不清除玩家 localStorage：通关、未完成拼图位置、道具、声音设置和引导记录均保留，也不删除其他应用的缓存。
- 拼图、原图预览与通关展示共用一张已解码的关卡图。离开关卡时释放纹理和图片，浏览器可复用压缩文件的 HTTP 缓存。首页优先预热当前与相邻魔方各自朝向玩家的三张高清封面，再补当前魔方背面。点击底部图标立即开始滑动，途中连点以最后一次选择为准。动画结束后释放邻域外的高清贴图，再补新魔方的其余面。五阶沿用敬请期待的牌背。
- 拼片共享一张 GPU 纹理，以独立 UV 连续取样。手机以屏幕短边和像素比设置绘图分辨率，整个游戏舞台的缓冲区宽度上限为 720 像素。横竖屏切换时由 CSS 缩放画面，魔方和拼图继续复用原缓冲区。
- 首页四套背景通过透明度完成 0.8 秒渐变。手机只在当前背景和淡出期间绘制装饰，用径向渐变实现柔光。首页使用一个 WebGL 画布绘制魔方，SVG 绘制装饰和庆祝星星。魔方外壳采用实例化绘制，加载时预先准备主题牌背纹理和着色器。
- 图片 URL 带内容版本，支持长期缓存；更新图片后版本自动变化。正式服务为文本资源提供 gzip、ETag 与 304。
- 原始 PNG 在 art-source/images/，仅在制作机本地保留用于后续修改，由 .gitignore 排除，不提交到 GitHub，也不进入 dist/。游戏运行、测试和构建使用仓库中的 public/assets/ WebP。旧公共目录 PNG 副本及独立缩略图目录已移除。旧缩略图备份在 .local/unused-thumbnails/，不参与构建。
- `art-source/experiments/` 的实验图片、重复备份、生成对应关系和检查报告仅在制作机本地保留，不提交 Git；只保留测试及关卡生成脚本直接读取的 8 份 JSON 基准，由 `.gitignore` 明确放行，确保克隆仓库后可验证。当前完整提示词和规范仍随仓库提交。
- 图片通过内置 imagegen 生成或参考原图编辑。192 张内容图片的当前提示词保存在 `art-source/catalog.json`。初版 5 张图的历史提示词在 `art-source/initial-prompts.txt`，历次编辑提示词保存在对应实验目录。压缩统计在 `art-source/optimization-report.json`。
- 白手套由内置 imagegen 生成，art-source/ui/ 中的 PNG 原图仅在本地保留，提示词随仓库提交；游戏使用 public/assets/ui/guide-hand.webp：384×384、透明 Alpha、约 11 KB。

重新导出素材时，先在 `art-source/images/` 恢复完整的 192 张源 PNG，再替换原图并运行以下命令。克隆后可直接使用仓库内的 WebP 运行、测试和构建游戏。

    npm run art:optimize
    npm run build

优化脚本只转换有变化的原图；面图的分辨率与质量方案也计入缓存版本，同时更新 src/art-manifest.json 的尺寸与内容版本。替换素材时维持文件 ID 即可。

## 代码与扩展

- src/progress.js：主题、章节、图片配置、道具库存、存档与解锁。
- src/first12-layouts.json：前 12 关独立配置与固定布局、解法及难度审核结果。
- src/later-layouts.json、scripts/level-plan.mjs：后 66 关布局、逐图辨识判断和章节难度节奏。
- scripts/generate-first12.mjs、scripts/level-search.mjs：可重现的离线生成、解法验证和短解筛选。
- scripts/generate-levels.mjs：后 66 关离线生成与检查点续接。
- src/puzzle.js：3×3 至 7×7 拼图交换与合组；大棋盘限制让位搜索开销。
- src/piece-geometry.js：连接边几何与 UV、照片棋盘布局。
- src/renderer.js：Three.js 拼片与拖动、PixiJS 落点提示与粒子。
- src/card-surface.js：圆角卡牌、薄边、倒角和整组外轮廓阴影，与拼接闪白共享边缘裁切。
- src/theme-art.js、src/card-back.js：主题图标与配色、魔方和拼片共用的主题牌背，适配照片比例。
- src/intro.js：关卡出场时序、随机翻面排程与逐块震动。
- src/cube-scene.js：3D 魔方、立体箭头、旋转、转面、放大、揭图和演出。
- src/main.js：首页 / 章节 / 关卡状态和图标交互。
- src/guide-state.js、src/idle-guide.js：引导触发、学习记录、合法拖动示意与手指动画。
- index.html、src/boot.js、src/loading.js、src/preload.js：首屏加载、无文字进度、资源校验、缓存恢复与后续关卡预取。
- scripts/serve.mjs：局域网静态服务、压缩与缓存。

CubeScene.showcase(kind) 为展示动画扩展点，kind 为 chapter 或 theme。它在 #cube-host 派发 cube-showcase-start/end，detail 包含主题与面编号；演出结束后才继续翻面或切换魔方。当前提供旋转、缩放和粒子效果。
